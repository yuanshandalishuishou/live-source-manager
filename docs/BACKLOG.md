# BACKLOG — V_1.1 本期不做项（有意遗留，后续版本评估）

> 记录 Stage 3（V_1.1）审计中识别、但经评估不在本期范围内的事项。
> 每条含理由与再评估条件，防止「悄悄遗忘」。

## 1. resolution_speed_map（分辨率-测速映射表）
- **现象**：Filter 段仅有 range 模式阈值，无「分辨率 → 最低测速」分级映射能力。
- **不做理由**：属增强需求而非缺陷；当前 range + must_hd/must_4k 已覆盖主要筛选场景，
  引入映射表会显著增加配置面与测试面。
- **再评估条件**：用户反馈「同带宽下高清源卡顿」且 range 模式无法表达时。

## 2. 性能模式 auto（Testing 段自动档）
- **现象**：concurrent_threads / max_concurrent_ffprobe 等仅支持手工数值，无 auto 档。
- **不做理由**：auto 档需要按 CPU/带宽动态调参，涉及调度反馈闭环，风险高于收益；
  默认值（50 线程 / 16 ffprobe）在目标硬件上已验证可用。
- **再评估条件**：部署环境硬件差异大（如 2 核 VPS）导致默认值不适用时。

## 3. jsonl 结构化日志
- **现象**：日志为纯文本格式，不便机器聚合分析。
- **不做理由**：当前日志人类可读性优先，运维规模未到需要 ELK/Loki 聚合的阶段。
- **再评估条件**：多实例部署或接入集中日志平台时。

## 4. armv7（linux/arm/v7）镜像
- **现象**：CI 仅构建 amd64/arm64，armv7 老设备（如早期 ARM 盒子）无镜像可用。
- **不做理由**：armv7 需交叉编译 Python 3.13 依赖（cryptography 等无预编译 wheel），
  构建时长与失败率不可控；目标用户群实测无 armv7 需求。
- **再评估条件**：出现明确的 armv7 部署诉求，且愿意接受自建镜像流程。

## 5. app/__init__.py __all__ 陈旧符号清理
- **现象**：`__all__` 仍含安全审计 S1/S2 已移除的符号（validate_url / is_safe_url /
  sanitize_url / 域名黑白名单系列等），`from app import *` 会 ImportError。
- **不做理由**：纯兼容性问题（项目内无 `import *` 用法）；清理属机械改动但涉及
  逐一核对下游引用，留待独立小版本处理，避免混入功能提交。
- **再评估条件**：任何依赖 `from app import *` 的外部代码出现时（即时修复）。

## 6. 播放截图 / RTMP 推流验证
- **现象**：测速仅 ffprobe 探测，不做实际拉流截图；不支持 RTMP 协议源测试。
- **不做理由**：截图需要 ffmpeg 渲染 + 存储，RTMP 需要额外协议栈；IPTV 源生态
  （HTTP/HLS 为主）下投入产出比低。ffprobe 已能识别绝大多数不可用源。
- **再评估条件**：出现「ffprobe 通过但实际播放失败」的批量反馈时评估截图验证。
